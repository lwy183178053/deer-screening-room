# Media library

支持扫描 `.mp4`、`.m4v`、`.mov`、`.mkv`、`.webm` 和 `.avi`。当前发布的播放格式为 H.264 或 AV1 视频加 AAC 或无音轨的 MP4/M4V/MOV；其他格式进入后台“不支持”状态，不会尝试实时转码。Windows 媒体库的标准化流程使用 RTX NVENC 将 MP4 转为最长边 1280 的 AV1 版本，音频统一为 AAC 双声道 48 kHz 128 kbps。

扫描器以规范化相对路径生成媒体键，并缓存修改时间、大小和 `ffprobe` 结果。默认每 10 分钟扫描一次，管理员可异步要求节点立即扫描；定时扫描与手动扫描串行执行，避免大型目录被重复探测。节点使用媒体键、大小和修改时间生成目录版本，未变化时只发心跳，发生变化时 Gateway 按工作室去重并批量 Upsert 视频。发布后的文件不应随意改名或移动；移动会被识别为旧媒体不可用和新媒体出现。

节点包启用兼容视图时，原始目录挂载到 `/source`，自动视图挂载到 `/media`。Linux/NAS 原生目录会在每次扫描前发现新增、变更和删除的视频；单个文件名超过 240 个 UTF-8 字节时生成稳定的 `media-<hash>` 别名，并通过 `catalog-titles.json` 恢复完整标题。视图优先创建硬链接，源目录与视图不在同一文件系统时使用软链接；视图卷可删除后重建，原始视频不受影响。Windows Docker 对超长目录可能在容器枚举 `/source` 前就返回 `input/output error`，此时由宿主机 `watch-media-view.cmd` 先生成短名视图，节点再读取该视图。

FFmpeg 在第 5 秒抽取 640 像素宽 JPEG 封面，单任务执行，并在 Linux/飞牛环境以较低 CPU 调度优先级运行。平台不提供人工标题、工作室、上下架或封面编辑，NAS 文件夹与文件名是唯一编目来源。

首页与工作室目录共用同一页面：默认目录使用每次进入首页生成的随机种子，加载更多沿用该种子；工作室按钮继续按 NAS 一级目录筛选，并保持原有更新时间排序。独立工作室页面和导航已移除。

节点每 30 秒独立发送心跳并报告扫描中、成功或错误，首次扫描或大型增量扫描不会阻塞在线状态更新；完整清单同步允许最多 5 分钟完成。

媒体节点只接受 `GET/HEAD /internal/media/{media_key}`、封面读取和重新扫描请求，并要求 `X-Relay-Token`。路径始终通过内存媒体键映射解析，不接受用户提供的文件路径。
