# Media library

媒体节点只接收 MP4 容器、AV1 视频和 AAC 音频。每个文件还必须包含非空的 MP4 `title` 与合法的 43 字符 Base64URL `deer_media_key`；不符合当前规范或 `ffprobe` 读取失败的文件会被跳过并记录到节点日志，不进入网站目录。Windows 媒体库的标准化流程使用 RTX NVENC 将视频转换为最长边 1280 的 AV1 版本，音频统一为 AAC 双声道 48 kHz 128 kbps。

扫描器通过 `ffprobe` 读取 MP4 的 `title` 和 `deer_media_key`。`deer_media_key` 是唯一稳定媒体键，购买权益因此不受可读文件名变化影响；网页标题只读取 `title`，不再从路径或文件名生成身份和标题。默认每 10 分钟扫描一次，管理员可异步要求节点立即扫描；定时扫描与手动扫描串行执行。节点使用媒体键、大小和修改时间生成目录版本，未变化时只发心跳，发生变化时 Gateway 批量 Upsert 视频。升级到严格规范后，旧目录缓存会重新探测一次，验证通过后才恢复增量缓存。

节点将媒体根目录只读挂载到 `/media`。Windows 新增视频由 `scripts/set-media-metadata.ps1` 写入元数据；文件名超过 240 个 UTF-8 字节时，在字符边界截断并追加 8 位路径哈希。Linux/NAS 节点只负责读取，不会重命名或改写媒体。

FFmpeg 在第 5 秒抽取 640 像素宽 JPEG 封面，单任务执行，并在 Linux/飞牛环境以较低 CPU 调度优先级运行。平台不提供人工标题、工作室、上下架或封面编辑；一级目录和 MP4 标题元数据是编目来源。

首页与工作室目录共用同一页面：默认目录使用每次进入首页生成的随机种子，加载更多沿用该种子；工作室按钮继续按 NAS 一级目录筛选，并保持原有更新时间排序。分类按钮根据当前屏幕宽度和实际文字宽度紧凑排列，桌面和手机默认显示两行，溢出时可展开全部；选择工作室不会自动收起分类区。独立工作室页面和导航已移除。

节点每 30 秒独立发送心跳并报告扫描中、成功或错误，首次扫描或大型增量扫描不会阻塞在线状态更新；完整清单同步允许最多 5 分钟完成。

媒体节点只接受 `GET/HEAD /internal/media/{media_key}`、封面读取和重新扫描请求，并要求 `X-Relay-Token`。路径始终通过内存媒体键映射解析，不接受用户提供的文件路径。
